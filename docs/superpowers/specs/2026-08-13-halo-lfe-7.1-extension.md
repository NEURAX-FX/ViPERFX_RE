# Halo LFE 7.1 Extension

Date: 2026-08-13

Status: Approved for implementation

## 1. Purpose

Extend the current Halo encoder from a 7.0 directional bed to a true 7.1 internal bed by restoring the reverse-engineered Halo LFE synthesis and low-frequency split stage.

The seven directional channels continue through the existing IEM render modes. LFE remains a non-directional mono sideband: it is never encoded into ACN/SN3D, never rotated, and never passed through KU100 as a virtual direction. It is latency-aligned to the directional decode, mixed equally into left and right, then processed by the existing headphone EQ, output gain, wet/dry stage, and limiter.

```text
stereo input
  -> Halo frequency-domain upmix
  -> continuous OLA 7.0 bed: L R C Ls Rs Lsr Rsr
  -> Halo diffusion / rear processing
  -> exact Halo LFE synth from L R C
       -> optional low-frequency split from L R C
       -> mono LFE sideband
  -> directional render branch
       Off:    7.0 bed fold
       Simple: ACN/SN3D -> rotation -> virtual-speaker fold
       KU100:  ACN/SN3D -> rotation -> KU100 decode
  -> delay LFE to the directional decoder output
  -> add LFE equally to L/R
  -> optional headphone EQ
  -> output gain / wet-dry alignment / limiter
```

## 2. Confirmed Decisions

- Restore Halo routine `0x180067544` from the updated HaloMixRE notes.
- The generated bed is semantically 7.1, but the API keeps seven directional planes plus an explicit `lfe` plane so LFE cannot accidentally enter spherical-harmonic encoding.
- LFE source channels are exactly `L`, `R`, and `C`. Surround and rear channels do not feed the LFE generator.
- All three source channels use identical Q=1 RBJ low-pass biquads.
- LFE is generated after continuous overlap-add and Halo diffusion/rear processing, matching the original stage order.
- `LfeSplit` subtracts each channel's own filtered low-frequency component from `L`, `R`, and `C`.
- `DownmixExact` is not exposed in this phase. Its original behavior is represented by `LfeSplit=0`, which leaves L/R/C unchanged.
- LFE is added to both decoded ears at unity after `LfeGain` has already been applied. No automatic cinema +10 dB boost is added.
- Existing Stereo, Multi, and Granular encoders remain unchanged and do not synthesize LFE.
- The feature remains HIDL-only with the existing AIDL hide policy.

## 3. Reverse-Engineered Algorithm

### 3.1 Normalized controls

For normalized `x` in `0..1`:

```text
cutoff_hz(x) = 10 * 20^x
gain_db(x)   = 55*x - 45
gain_lin(x)  = 10^(gain_db(x)/20)
split(x)     = x
```

Original defaults:

```text
Lfe       = enabled
LfeFreq   = 0.75        -> 94.5742 Hz
LfeSplit  = 0           -> no subtraction from L/R/C
LfeGain   = 0.272727281 -> -30 dB -> 0.0316228 linear
```

### 3.2 Exact low-pass biquad

For each of L, R, and C, with `Q=1`, sample rate `Fs`, and mapped cutoff `fc`:

```text
w0    = 2*pi*fc/Fs
alpha = sin(w0)/(2*Q)
c     = cos(w0)
d     = 1 + alpha

b0  = (1-c)/(2*d)
b1  = (1-c)/d
b2  = b0
fb1 =  2*c/d
fb2 = -(1-alpha)/d

y[n] = b0*x[n] + b1*x[n-1] + b2*x[n-2]
     + fb1*y[n-1] + fb2*y[n-2]
```

The reverse-engineered binary fixture is for `Fs=48 kHz` and the default cutoff. All three filters must match:

```text
b0  = 0.0000380900201
b1  = 0.0000761800402
b2  = 0.0000380900201
fb1 = 1.98754442
fb2 = -0.987696767
```

The IEM graph runs at `Fs=96 kHz`. Applying the same documented single-precision operation order at 96 kHz gives the project fixture:

```text
fc    = 94.5741653 Hz
w0    = 0.00618986459
alpha = 0.00309491251
c     = 0.999980867

b0  = 0.00000953702965
b1  = 0.0000190740593
b2  = 0.00000953702965
fb1 = 1.99379110
fb2 = -0.993829250
```

### 3.3 Per-sample routing

After the three filter outputs `fL`, `fR`, and `fC` are produced:

```text
lfe[n] = (fL + fR + fC) * gain_lin

L[n] = L[n] - fL * split
R[n] = R[n] - fR * split
C[n] = C[n] - fC * split
```

When disabled, L/R/C are unchanged and LFE is cleared to zero. State reset clears all three biquad histories.

## 4. Native Architecture

### 4.1 Bed representation

Keep the existing directional enum and count unchanged:

```cpp
constexpr uint32_t kHaloDirectionalChannels = 7;

struct HaloBedView {
    float *directional[kHaloDirectionalChannels];
    float *lfe;
};
```

`EncodeHaloBedToSn3d()` accepts only the directional planes. `FoldHaloBedToStereo()` also remains directional-only. LFE has a separate mixing helper so a future refactor cannot assign it an azimuth.

### 4.2 HaloLfeSynth

Add a dedicated prepared stage:

```cpp
struct HaloLfeCoefficients {
    float b0;
    float b1;
    float b2;
    float fb1;
    float fb2;
};

struct HaloLfeParams {
    bool enabled = true;
    int32_t frequency_millionths = 750000;
    int32_t split_millionths = 0;
    int32_t gain_millionths = 272727;
    HaloLfeCoefficients coefficients_96k{
        0.00000953702965F,
        0.0000190740593F,
        0.00000953702965F,
        1.99379110F,
        -0.993829250F,
    };
};

class HaloLfeSynth {
public:
    bool Prepare(uint32_t sample_rate) noexcept;
    void ApplyParams(const HaloLfeParams &params) noexcept;
    void Reset() noexcept;
    void Process(
        float *left,
        float *right,
        float *centre,
        float *lfe,
        std::size_t frames
    ) noexcept;
};
```

Millionths preserve the reverse-engineered defaults and mappings more accurately than the existing thousandths Halo controls. App and driver both clamp to `0..1,000,000`; the driver remains authoritative.

Coefficient generation happens on the control/dispatch side. `UpdateIemParameterSnapshot()` maps the normalized cutoff to a derived 96 kHz `HaloLfeCoefficients` value before publishing the parameter snapshot to `ParameterMailbox`. The audio callback's `ApplyParams()` only copies those five floats and scalar targets; it performs no trig/log/exp. The per-sample loop uses the copied coefficients and four scalar histories per channel.

### 4.3 HaloEncoder integration

`HaloEncoder` adds one prepared LFE plane and calls `HaloLfeSynth::Process()` after continuous OLA/diffusion, not inside an overlapping STFT frame. Its result is returned alongside the seven directional planes.

The existing 1536-frame Halo encoder latency applies equally to the directional bed and generated LFE because synthesis occurs after both share the same OLA timeline.

### 4.4 Render modes and latency

**Off**

- Fold only the seven directional planes with the existing Off matrix.
- Add LFE equally to L/R immediately after the fold.

**Simple**

- Encode only the seven directional planes to ACN/SN3D.
- Rotate and Simple-decode them.
- Add LFE equally to L/R after Simple decode.

**KU100**

- Encode/rotate/decode only the directional planes.
- Delay LFE by the KU100 decoder latency so its sample timeline matches the binaural output.
- Add delayed LFE equally to decoded L/R.
- Run the combined signal through headphone EQ so headphone correction also applies to LFE.

LFE delay storage is allocated during prepare. Render-mode changes rebuild the graph as they do today. LFE parameter edits are dynamic and do not rebuild the graph.

## 5. Parameter Protocol and Persistence

Use the next unused Halo IDs:

| ID | Meaning | Wire value | Default |
|---|---|---|---|
| `0x1207E` | Halo LFE Enable | 0/1 | 1 |
| `0x1207F` | Halo LFE Frequency | normalized millionths, `0..1,000,000` | 750000 |
| `0x12080` | Halo LFE Split | normalized millionths, `0..1,000,000` | 0 |
| `0x12081` | Halo LFE Gain | normalized millionths, `0..1,000,000` | 272727 |

These fields persist in device settings and preset JSON. Presets created before this extension receive the original Halo defaults above. Full-state HIDL restore writes them with the other Halo parameters between Enable=0 and the final target Enable.

## 6. App UX

The encoder name shown to users becomes `Halo 7.1`. The compact main card remains limited to Encoder Mode, Order, Wet, and Open Editor.

The Halo portion of the Encoder tab adds four flat controls:

- LFE switch.
- LFE Frequency logarithmic slider, displayed in Hz.
- LFE Split linear slider, displayed as percent.
- LFE Gain linear-in-dB slider, displayed in dB.

No nested cards and no hidden long-press behavior. English, simplified Chinese, and Russian resources are required. Product name `Halo` remains untranslated.

## 7. Tests and Acceptance

### 7.1 Native unit tests

- Default coefficient generation matches both the documented 48 kHz binary fixture and the derived 96 kHz project fixture.
- Frequency endpoints map exactly to 10 Hz and 200 Hz.
- Gain endpoints map to -45 dB and +10 dB; default maps to approximately -30 dB.
- Impulses in L, R, and C each feed only their own filter state and contribute to LFE.
- Surround/rear impulses do not generate LFE.
- `split=0` leaves L/R/C bit-identical apart from signed-zero differences.
- `split=1` subtracts each channel's own filtered component.
- Disabled stage clears LFE and leaves L/R/C unchanged.
- Processing one block or arbitrary chunks produces identical output.
- Reset clears histories.
- No allocation, lock, I/O, trig/log/exp, or random source in `Process()`.

### 7.2 Pipeline tests

- Yaw, pitch, roll, and Ambisonics order changes do not alter LFE.
- Off, Simple, and KU100 produce the same aligned LFE waveform before their common post stages.
- KU100 delays LFE by the decoder latency before mixing.
- Headphone EQ processes the combined KU100+LFE signal exactly once.
- LFE is not double-counted in any render mode.
- Halo wet/dry latency remains aligned with the corrected 1536-frame encoder latency.

### 7.3 App tests

- Defaults, normalization, preset round-trip, full restore, and incremental dispatch cover all four IDs.
- `Halo 7.1` summary text is correct.
- Every visible LFE control has English, simplified Chinese, and Russian resources.
- AIDL continues to hide the IEM card.

### 7.4 Release gates

- Full host CTest and UBSan.
- ASan compile/link with the existing host SIGILL limitation documented if unchanged.
- Android Release builds for arm64-v8a and armeabi-v7a.
- App unit tests, lint, and `assembleDebug`.
- Bind-mount smoke without claiming listening results that cannot be objectively measured.

## 8. Error and Transition Semantics

- Invalid normalized values are clamped.
- Non-finite coefficients or samples trigger the existing IEM fault path and dry fallback.
- Frequency changes switch coefficient sets only at a block boundary; filter state is preserved to avoid a low-frequency transient.
- Enable changes ramp LFE contribution over one internal block. Disabling does not leave stale samples in the LFE delay line.
- A graph prepare failure keeps the previous graph active.

## 9. Explicit Non-Goals

- Feeding Halo output into the current stereo Granular encoder.
- Encoding LFE into the Ambisonics W channel.
- Automatic cinema +10 dB LFE playback boost.
- Restoring Halo's complete final stereo downmix or monitor/solo system.
- Synthesizing LFE for Stereo, Multi, or Granular encoder modes.
- Adding overhead channels, C LF divergence, or multichannel host input in this extension.

## 10. Completion Criteria

This extension is complete only when:

1. Halo produces seven directional channels plus an exact reverse-engineered LFE sideband.
2. The three Q=1 RBJ filters and normalized mappings match the updated HaloMixRE fixtures.
3. LFE remains non-directional and sample-aligned in Off, Simple, and KU100.
4. The four controls persist and dispatch correctly and appear in all three supported locales.
5. No regression appears in non-Halo encoders or the HIDL-only/AIDL-hide policy.
6. All native, Android ABI, and App gates pass.
